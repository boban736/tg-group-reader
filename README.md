# tg-group-reader

Раз в час читает Telegram-группу (от твоего аккаунта, через Telethon), отдаёт новые сообщения вместе с фото и текстом файлов в GPT и пишет полезное в дневную заметку Obsidian. О срочном пишет в «Избранное».

## Установка (macOS)

1. Получи `api_id`/`api_hash` на https://my.telegram.org → API development tools.
2. `./scripts/install.sh` — создаст `.env`; заполни его и запусти ещё раз. При первом запуске Telegram спросит номер и код, сессия сохранится в `tg.session` (**не отдавай этот файл никому — это доступ к аккаунту**).
3. Первый прогон вручную, с бэкфиллом: `.venv/bin/python reader.py --days 7` (сначала можно с `--dry-run` — покажет diff и ничего не запишет).
4. `./scripts/install.sh` ещё раз — поставит launchd-задачу: раз в час и при входе в систему. Если Mac спал, скрипт подберёт пропущенное с последнего обработанного сообщения.

## Что получается в vault

Раскладка настроена под vault USM (`Courses/<Предмет>/<Предмет>.md`, `Log/YYYY-MM-DD.md`). Список предметов берётся из хабов курсов при каждом запуске — новые предметы подхватываются сами.

- `Log/Telegram/TG YYYY-MM-DD.md` — дайджест за день исходных сообщений (frontmatter `kind: digest`, тег `telegram`): блоки по прогонам, разбивка по категориям, `[[Предмет]]`, ссылки на сообщения, встроенные фото.
- `Log/YYYY-MM-DD.md` — в конец дописывается строка `- HH:MM — Telegram: N записей → [[TG …]]` и срочное (🔴).
- `Дедлайны.md` — `- [ ] [[Предмет]]: … 📅 YYYY-MM-DD`; дубли (тот же предмет и дата, похожее название) и прошедшие даты пропускаются, галочки не трогаются. Если в `Assignments/` есть задание с той же датой — ставится ссылка на него.
- `Courses/<Предмет>/<Предмет>.md` — секция `## Из Telegram` (создаётся в конце файла, после блока `links`): новые дедлайны и материалы.
- Файлы — в `Courses/<Предмет>/Materials/Telegram/`, без предмета — в `Inbox/Telegram/`.

Существующий текст заметок не переписывается: только новые файлы и дописывание. Запись атомарная; если файл поменялся во время прогона, дописывание накладывается поверх свежей версии.

## Настройка

- Что считать полезным, синонимы предметов: `prompts/system.md`.
- Пути, теги, флаги `WRITE_LOG` / `WRITE_DEADLINES` / `WRITE_COURSE_SECTIONS`, лимиты: `.env` (см. `.env.example`).
- Ручной запуск: `.venv/bin/python reader.py [--days N] [--dry-run] [--no-notify]`; лог: `reader.log`.
- Начать заново: удалить `state.json`, тогда возьмутся последние `FIRST_RUN_HOURS` часов.
- Тесты: `.venv/bin/python -m pytest tests`.
